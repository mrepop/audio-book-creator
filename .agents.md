# Audio Book Creator - Agent Context

This file provides context for AI agents working on this project.

## Project Overview

Audiobook generation app using Qwen3-TTS on Apple Silicon (MPS). Converts EPUB books into spoken audiobooks with character voice assignment, sentence-level control, and a React frontend.

## Architecture

- FastAPI backend (src/api/) with SQLite database
- React + Vite + TailwindCSS frontend (frontend/)
- Qwen3-TTS-12Hz-1.7B-CustomVoice model for TTS
- Background worker threads for generation jobs
- Singleton TTS engine shared across all threads

## Critical Technical Decisions

### PyTorch MPS Patch (IMPORTANT)
The system runs a **locally patched PyTorch** built from source at `/tmp/pytorch-patch`. The patch (from PyTorch PR #181485) adds `MPSGraphCache::clear()` to `torch.mps.empty_cache()`. Without this patch, MPS Metal driver memory grows unboundedly (~300MB per generate call) and the system will OOM. The patch source modifies:
- `aten/src/ATen/native/mps/OperationUtils.h` - adds `clear()` method to MPSGraphCache
- `aten/src/ATen/mps/MPSHooks.mm` - calls clear() from emptyCache()

If PyTorch is reinstalled via pip, this patch will be lost and memory issues will return. Check `torch.__version__` - if it shows `2.11.0a0+git70d99e9` the patch is active; if it shows `2.11.0` it's the stock version without the fix.

### MPS Thread Safety
Metal command buffers crash with "commit command buffer with uncommitted encoder" if two threads submit simultaneously. All generate_custom_voice calls go through `Qwen3TTSEngine._generate_lock` (a threading.Lock). This means GPU work is serialized even with 40 concurrent jobs - only CPU work (chunking, splicing, file I/O, DB) runs in parallel.

### Sentence-Level Chunking
Text is split at sentence boundaries into 12-15 second chunks before TTS. This is required because Qwen3 produces artifacts (gibberish, stuttering, repetition) on segments longer than ~30 seconds. The chunker is at `src/tts/chunker.py`. VCS-Audio (sister project at ~/projects/vcs-audio) validated this approach.

### Audio Quality Parameters
- `repetition_penalty=1.05` - prevents Qwen3 token loops that cause stuttering
- `max_new_tokens` capped per chunk at `est_duration * 12Hz * 2.5x` - prevents runaway generation
- `temperature=0.7` - lower than default for voice consistency across chunks
- `seed=42` with per-chunk offset (+i) for deterministic but varied output

### Memory Management
- Segment audio is written to disk immediately, never held in memory arrays
- `torch.mps.empty_cache()` called after each batch of 16 segments
- System-level memory guard checks `psutil.virtual_memory().available` before each segment
- Model cycling (`_cycle_tts_engine`) is available as fallback but not needed with the patched PyTorch

## Common Issues and Solutions

### Memory grows unboundedly
Check if patched PyTorch is active: `python -c "import torch; print(torch.__version__)"`. Should show `2.11.0a0+git70d99e9`. If it shows `2.11.0`, rebuild from `/tmp/pytorch-patch`.

### Metal command buffer crash
"commit command buffer with uncommitted encoder" - means two threads hit the GPU simultaneously. Ensure all generate calls go through `_generate_lock`.

### Audio has gibberish/stuttering
Check that `repetition_penalty=1.05` is being passed and `max_new_tokens` is capped (not 2048 for every call).

### Generation hangs with no progress
Check for zombie worker threads. The cancel_event system should prevent this. If a generate_custom_voice call hangs internally, the only option is to kill the process.

### Frontend can't connect
Backend runs on :8000, frontend on :5173 with proxy to backend. Both bind to 0.0.0.0. Check `scripts/dev.sh`.

### Book doesn't appear in Generation Studio dropdown
The dropdown filters on `is_parsed`. If the book was parsed but `is_analyzed` is null, it still shows. If `is_parsed` is false, parse the book first from the Library page.
